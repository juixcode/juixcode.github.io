Rappels A1 express

Pas de cours de syntaxe ici : seulement les fondamentaux de l'an dernier qui font perdre des points en A2.

Type valeur vs type référence

Les types simples (int, double, bool, char) sont copiés par valeur. Les tableaux, les string et tous les objets sont manipulés par référence : copier la variable copie l'adresse, pas le contenu.

À retenirUn objet passé en paramètre peut être modifié par la méthode (elle reçoit la référence). Pas besoin de ref pour changer ses attributs.

Division entière, conversions & saisie

int / int donne toujours un entier. Pour une moyenne, il faut caster avant de diviser. Tout ce que tape l'utilisateur est un string : il faut le convertir.

Vérifier le type d'une saisie : TryParse tombe souvent

Classique de contrôle : « vérifiez que l'utilisateur a bien saisi un entier ». int.Parse("abc") fait planter le programme. int.TryParse essaie la conversion sans jamais planter :

  • elle renvoie un bool : true si la saisie est du bon type, false sinon ;
  • la valeur convertie sort par le paramètre out (elle vaut 0 en cas d'échec).
En contrôle« Vérifier la saisie » = TryParse dans la condition d'un while (ou d'un do…while). Ajoute la contrainte métier avec || (positif, entre 0 et 20…). TryParse renvoie aussi false pour un nombre trop grand, là où Parse lèverait une OverflowException.

Chaînes de caractères (string)

Une string est immuable : chaque méthode renvoie une nouvelle chaîne, l'originale ne change pas. On lit un caractère comme dans un tableau, mais on ne peut pas l'écrire.

Pièges.ToUpper(); seul ne fait rien d'utile : il faut récupérer le résultat → s = s.ToUpper();

Penser objet & modéliser en UML

Pourquoi la POO, ce qu'est une classe, et comment passer d'un diagramme de classes à du code C#.

Pourquoi la POO ?

En programmation séquentielle (A1), les données circulent entre des fonctions. Dès que le programme grossit (gestion de comptes bancaires, de dossiers médicaux…), ça devient ingérable.

Séquentiel : les limites
  • Données du client mélangées à celles du compte
  • Débogage difficile : il faut suivre les enchaînements d'appels
  • Ajouter une fonction oblige à revoir ses liens avec les autres
  • Aucune séparation claire des rôles
Objet : la solution
  • Chaque objet regroupe ses données + ses actions
  • Les objets interagissent entre eux (Client, Compte, Banque)
  • Code plus facile à faire évoluer, concevoir et maintenir

Classe vs objet

Une classe est le plan (le moule, le type). Un objet est une instance concrète créée en mémoire à partir de ce plan. Client est une classe ; « Julien, 2 rue de la Paix » est un objet.

attributsVariables qui décrivent l'état de l'objet (nom, solde…). Toujours private.
constructeur(s)Méthode spéciale appelée par new : crée et initialise l'objet.
propriétésLire (get) et/ou modifier (set) un attribut privé de façon contrôlée.
méthodesLes actions que l'objet sait faire (afficher, déposer, retirer…).

Lire une classe UML

Une classe se dessine en 3 cases : nom, attributs, opérations (constructeurs, propriétés, méthodes). Le symbole devant chaque membre donne sa visibilité.

Les relations entre classes

La cardinalité placée près d'une classe dit combien d'objets de cette classe sont liés à un objet de l'autre classe : 1, 0..1, 0..*, 1..*.

Association

Relation durable « utilise / travaille pour ». Ex. : une Personne travaille dans 0..* Entreprises, une Entreprise emploie 1..* Personnes.

Agrégation (losange vide côté conteneur)

« contient », mais la partie survit sans le tout. Un Employé peut quitter l'Entreprise et continuer d'exister.

Composition (losange plein)

Agrégation forte : la partie appartient à un seul tout et meurt avec lui. Une Pièce n'existe pas sans sa Maison.

Héritage (triangle vide vers la mère)

« est un » : un CompteCheque est un Compte. Voir chapitre 7.

Méthode pour modéliser un énoncé Problème

  1. Repère les noms importants → candidats classes (Hôtel, Chambre, Client, Réservation, Paiement).
  2. Leurs caractéristiques → attributs avec un type et -.
  3. Les verbes (« ajouter », « rechercher », « calculer le montant ») → méthodes avec paramètres et type de retour.
  4. Trace les relations et leurs cardinalités (« une réservation concerne un seul client » → 1).
  5. Vérifie que chaque besoin de l'énoncé est couvert par une méthode.
Barème du ProblèmeProgramme fonctionnel 5 pts · diagramme des classes 3 pts · bon choix des conteneurs 2 pts · questions 10 pts. Un diagramme propre et une bonne collection = 5 points « faciles ».

Anatomie d'une classe & encapsulation

Attributs, constructeurs, propriétés, méthodes, static, ToString : le squelette de TOUTES tes classes.

Le squelette complet d'une classe

L'ordre conseillé : attributs → constructeurs → propriétés → méthodes. Exemple tiré du TD3-4 (classe Article).

Pièges de compilation
  • Un constructeur n'a pas de type de retour (même pas void).
  • prixHT * 1.2 est un double → impossible de le renvoyer en float sans 1.2f ou un cast.
  • Si tu écris un constructeur avec paramètres, le constructeur par défaut new Article() n'existe plus (sauf si tu l'écris).

Les constructeurs

Appelés par new, ils réservent la mémoire et initialisent les attributs. On peut en avoir plusieurs (surcharge) pour créer un objet selon les données disponibles.

: this(nom, "", tel)Un constructeur peut en appeler un autre de la même classe (évite de dupliquer).
thisthis désigne l'objet courant. Indispensable quand le paramètre a le même nom que l'attribut : this.nom = nom; (sinon on s'affecte le paramètre à lui-même).

Propriétés get / set

Une propriété porte le nom de l'attribut avec une majuscule. get renvoie la valeur, set la modifie : la valeur reçue s'appelle toujours value. C'est l'endroit idéal pour valider.

Lire l'énoncé« accessible en lecture » → get seul · « peut être modifié » → get + set · « ne peut pas être modifié après la création » → pas de set.
Piège vu en CMSi l'attribut s'appelle lui-même value, le setter set { value = value; } ne fait rien ! Il faut this.value = value; — ou mieux, nommer l'attribut autrement.

Raccourci moderne (si aucune validation) : public string Tel { get; set; } — l'attribut est créé automatiquement.

static : membres de classe vs d'instance

Un membre static appartient à la classe et est partagé par tous les objets (ex. : compter les objets créés). Un membre d'instance appartient à chaque objet.

Règles d'or
  • Une méthode static ne peut pas utiliser les attributs d'instance (pas de this).
  • Main est static → les fonctions que tu appelles directement depuis Main doivent être static.

ToString() & Equals()

Console.WriteLine(obj) appelle automatiquement obj.ToString(). Pour que ça affiche ta description, il faut redéfinir la méthode héritée de Object avec override.

EqualsDeux objets « identiques » selon l'énoncé (même référence, même numéro d'étudiant…) se comparent avec une méthode Equals qui compare l'attribut clé, jamais avec == (qui compare les références, voir 3.2).

Le principe d'encapsulation

Les attributs sont privés et ne sont accessibles que via les propriétés et méthodes que la classe propose. Résultat : l'objet garantit l'intégrité de ses données (pas de population négative, pas de solde modifié n'importe comment).

Sans encapsulation
  • public double solde;
  • c.solde = -5000; → incohérent, personne ne l'empêche
Avec encapsulation
  • private double solde; + méthodes Crediter / Debiter
  • Le débit vérifie le solde avant d'agir

Manipuler un objet

On accède aux membres avec le point : objet.Methode(), objet.Propriete. Les attributs privés sont inaccessibles de l'extérieur : c.nom → erreur de compilation (violation de l'encapsulation).

Tableau d'objets & tri selon un attribut

Classique des TD (ServiceStage, Région) : un tableau à taille fixe + un compteur de cases remplies, puis un tri « à la main » (sans Sort) sur un attribut.

Ordre alphabétiquestring.Compare(a.Nom, b.Nom) renvoie < 0 si a est avant b, 0 si égaux, > 0 sinon. Remplace simplement la comparaison < du tri : if (string.Compare(t[j].Nom, t[iMin].Nom) < 0).

Surcharge de méthodes

Plusieurs méthodes peuvent porter le même nom si leurs paramètres diffèrent (nombre ou types). C# choisit la bonne selon les arguments. Marche aussi pour les constructeurs et les méthodes static.

Surcharge d'opérateurs

On peut définir ==, !=, +, -, <… pour sa classe. C'est une méthode public static nommée operator suivie du symbole.

PiègeLes opérateurs vont par paires : == exige !=, < exige >, sinon erreur de compilation. Toujours public static.

CM3 · TD5-6 ★ Priorité examen

La récursivité

Une fonction qui s'appelle elle-même sur un problème plus petit. Classique vs terminale, pile d'appels, mémoïsation, diviser pour régner.

Le principe en 2 règles

Une fonction récursive résout un problème en le ramenant au même problème, en plus simple. Pour calculer n!, il suffit de savoir calculer (n-1)! puis de multiplier par n.

  1. Une condition d'arrêt : le cas le plus simple, résolu sans appel récursif.
  2. Un appel récursif avec des paramètres qui se rapprochent de la condition d'arrêt.
PiègeSans condition d'arrêt atteignable (ou avec Factorielle(n) au lieu de n - 1), les appels sont infinis → StackOverflowException.

La pile d'appels : empilement / dépilement

Chaque appel réserve une zone mémoire (paramètres, variables locales, résultat) dans la pile. Les appels s'empilent jusqu'à la condition d'arrêt, puis se dépilent en renvoyant leurs résultats.

Empilement ↓
Factorielle(4) → attend 4 * F(3)
Factorielle(3) → attend 3 * F(2)
Factorielle(2) → attend 2 * F(1)
Factorielle(1) → arrêt
Dépilement ↑
Factorielle(1) renvoie 1
Factorielle(2) renvoie 2 * 1 = 2
Factorielle(3) renvoie 3 * 2 = 6
Factorielle(4) renvoie 4 * 6 = 24
En examenOn te demande souvent de dessiner la pile pour un appel donné : écris chaque appel avec ses paramètres en descendant, puis les valeurs renvoyées en remontant. Le débogueur de Visual Studio (fenêtre « Pile des appels ») montre exactement ça.

Récursivité classique vs terminale tombe souvent

Classique (non terminale)Terminale
Appel récursiffait partie d'un calcul : n * F(n - 1)est la dernière action, seul : return F(n - 1, acc * n);
Le résultat se construiten remontant (au dépilement)en descendant, dans un accumulateur
Condition d'arrêt renvoiela valeur du cas simple (1)l'accumulateur
Appel initialFactorielle(5)Factorielle(5, 1) (acc = élément neutre)
Recette : classique → terminale
  1. Ajoute un paramètre accumulateur (0 pour une somme, 1 pour un produit, -1 / 0 pour un compteur…).
  2. Fais le calcul dans l'argument de l'appel : F(n - 1, acc * n).
  3. La condition d'arrêt renvoie l'accumulateur.
Le CM recommande la terminale (moins de travail au dépilement).

Récursivité sur un tableau ou une chaîne

On ajoute un indice en paramètre qui avance à chaque appel ; on s'arrête quand il atteint la fin. Tous les exercices du TD5-6 suivent ce modèle.

« Un seul return par fonction »Bonne pratique demandée en TD : stocke le résultat dans une variable.
int res = 1; if (n > 1) res = n * Factorielle(n - 1); return res;

Récursivité multiple & mémoïsation

Une fonction est multiple quand elle s'appelle plusieurs fois par exécution (Fibonacci : F(n) = F(n-1) + F(n-2)). L'arbre des appels explose : les mêmes valeurs sont recalculées des milliers de fois. La mémoïsation stocke chaque résultat déjà calculé dans un tableau (le « buffer ») pour le réutiliser.

Comparer les appelsPour prouver le gain, ajoute un compteur static int nbAppels incrémenté au début de la fonction, et affiche-le avec et sans mémoïsation.

Diviser pour régner

3 étapes : Diviser le problème en sous-problèmes plus petits · Régner en les résolvant (récursivement) · Combiner leurs solutions.

Complexité du tri fusionOn coupe en deux jusqu'à des tableaux de taille 1 → log₂(n) niveaux. À chaque niveau, la fusion traite les n éléments → O(n log n) dans tous les cas. Mémoire supplémentaire : le tableau temporaire → O(n).
Piège puissance rapideÉcrire PuissanceRapide(x, n/2) * PuissanceRapide(x, n/2) refait deux fois le même calcul et annule tout le gain : stocke le résultat dans une variable.

Méthode pour écrire n'importe quelle fonction récursive

  1. Cas d'arrêt : quel est le cas trivial ? (tableau parcouru, n == 0, deb >= fin…)
  2. Hypothèse : « si je sais résoudre le problème pour n - 1 (ou pour la suite du tableau), comment j'obtiens le résultat pour n ? »
  3. Paramètres qui progressent : indice qui avance, taille qui diminue, bornes qui se resserrent.
  4. Terminale demandée ? → ajoute un accumulateur et renvoie-le à l'arrêt.
  5. Teste à la main sur un tout petit exemple et dessine la pile.
  6. Explique la signature : rôle de chaque paramètre + appel initial (le TD le demande).

Les collections

Des conteneurs dont la taille varie : ArrayList, Stack, Queue, List<T>, Dictionary… et comment choisir le bon.

Pourquoi pas un tableau ?

Un tableau a une taille fixe. Pour ajouter un 4e compte dans un tableau de 3, il faut créer un tableau plus grand, tout recopier, puis remplacer l'ancien. Les tableaux n'offrent pas non plus de tri, d'ajout ou de suppression intégrés.

List<T> : le couteau suisse

Le tableau dynamique typé. C'est le conteneur à utiliser par défaut dès que le nombre d'éléments varie.

Associe une clé unique à une valeur. Retrouver une valeur à partir de sa clé est immédiat. Parfait pour le TD « annuaire » : numéro (clé, unique) → nom.

Héritage & polymorphisme

Classes mères et filles, protected, : base(…), virtual / override, sur-classement et listes polymorphes.

Pourquoi hériter ?

La banque propose des CompteCheque (frais de tenue de compte) et des LivretA (intérêts). Sans héritage, on recopie nom, prénom, adresse, numéro et solde dans chaque classe, et la Banque a besoin d'une liste par type de compte.

Or un CompteCheque est un Compte, avec des spécificités. L'héritage crée une nouvelle classe à partir d'une classe existante en lui transmettant ses attributs et ses méthodes.

Syntaxe : : Mere, protected et : base(…)

  • La fille possède tous les membres de la mère (+ les siens). La mère ne connaît pas ceux de la fille.
  • Les attributs private de la mère existent dans la fille mais ne sont accessibles que via les propriétés. Avec protected, la fille y accède directement.
  • Le constructeur de la mère s'exécute d'abord, puis celui de la fille.
  • Paramètres de base(…) : dans l'ordre du constructeur de la mère.
  • Si la mère n'a qu'un constructeur avec paramètres, : base(…) est obligatoire. Si elle a un constructeur sans paramètre (ou aucun), il est appelé automatiquement.
  • Pas d'héritage multiple en C# : une seule classe mère.
Erreur classiqueOublier : base(couleur) alors que Forme n'a pas de constructeur vide → « Forme ne contient pas de constructeur qui accepte 0 argument ».

Tout hérite de Object

Une classe sans : Mere hérite implicitement de Object. Toute classe hérite donc (directement ou non) de ses méthodes :

ToString()Par défaut, renvoie le nom complet de la classe. Console.WriteLine(o) ≡ Console.WriteLine(o.ToString()).
Equals(object)Par défaut, true si les deux références désignent le même objet.
GetType()Renvoie le type réel de l'objet (o.GetType().Name → "Cercle").
overrideC'est pour ça qu'on écrit public override string ToString() : on redéfinit la version d'Object.

Redéfinir une méthode : virtual / override

Le polymorphisme (« plusieurs formes ») : une même méthode se comporte différemment selon la classe fille. La fille garde la même signature (nom, paramètres, type de retour) mais change le corps.

MèreFilleRésultat
virtualoverride✔ polymorphisme : la version de la fille est appelée, même via une variable de type mère
virtualrien (ou new)✘ masquage : via une variable de type mère, c'est la version de la mère qui s'exécute (avertissement du compilateur)
rienoverride✘ erreur de compilation : on ne peut redéfinir qu'une méthode virtual, abstract ou override

En UML : + virtual Affiche() : void dans la mère et + override Affiche() : void dans la fille.

Sur-classement : une fille est une mère

Une variable de type mère peut contenir un objet de type fille. À l'appel d'une méthode redéfinie, C# exécute la version du type réel de l'objet (liaison dynamique).

LimiteVia une variable de type mère, on ne peut appeler que ce que la mère connaît : p.Couleur ou c.CalculInteret() ne compilent pas si ces membres n'existent que dans la fille → il faut sous-classer (notion suivante).

Q1Différence entre private et protected ?›

private : accessible uniquement dans la classe. protected : dans la classe et ses classes filles (# en UML). → ch. 2 et 7

Q2Que valent 7 / 2 et (double)7 / 2 ?›

3 (division entière) et 3.5. → ch. 0

Q3Console.WriteLine(c) affiche « MonProjet.Client ». Pourquoi ?›

ToString() n'est pas redéfinie (ou écrite toString). Il faut public override string ToString(). → ch. 2

Q4Que fait new StreamWriter("f.txt", true) ?›

Ouvre f.txt en mode ajout : on écrit à la fin sans effacer (le fichier est créé s'il n'existe pas). Sans true : le contenu est écrasé. → ch. 6

Q5Récursivité terminale vs classique ?›

Terminale : l'appel récursif est la dernière action, seul (return F(n - 1, acc * n);), le résultat voyage dans un accumulateur. Classique : l'appel fait partie d'un calcul (n * F(n - 1)), le résultat se construit au dépilement. → ch. 4

Q6Quelle collection pour un guichet ? pour « annuler la dernière action » ? pour un annuaire numéro → nom ?›

Queue<T> (FIFO) · Stack<T> (LIFO) · Dictionary<string, string> (clé unique). → ch. 5

Q7Après Push(1); Push(2); Push(3); Pop();, que renvoie Peek() ?›

2 : Pop a retiré le 3 (sommet), Peek lit le nouveau sommet sans le retirer. → ch. 5

Q8Pourquoi faut-il caster quand on lit un ArrayList ?›

Il stocke des object : le programme ne connaît plus le type réel de l'élément. (Compte)liste[0]. Les collections génériques (List<T>) évitent ce cast. → ch. 5

Q9Comment appeler le constructeur de la classe mère ?›

Avec : base(paramètres) après la signature du constructeur de la fille, paramètres dans l'ordre de la mère : public Cercle(string couleur, double rayon) : base(couleur). → ch. 7

Q10Point p = new PointColore(1, 2, "bleu"); Console.WriteLine(p); — quel ToString est appelé ?›

Celui de PointColore (type réel), à condition qu'il soit en override. C'est le polymorphisme / sur-classement. → ch. 7

Q11Qu'est-ce que la mémoïsation ?›

Stocker dans un tableau les résultats déjà calculés d'une fonction récursive multiple pour ne pas les recalculer (Fibonacci : 2,7 millions d'appels → 59). → ch. 4

Q12Dans quel ordre écrire plusieurs catch ?›

Du plus précis (FileNotFoundException, FormatException) au plus général (Exception, toujours en dernier). → ch. 6

Q13Agrégation ou composition : une Maison et ses Pièces ?›

Composition (losange plein) : une pièce appartient à une seule maison et disparaît avec elle. Entreprise / Employé = agrégation (losange vide). → ch. 1

Q14Complexité du tri fusion en temps et en mémoire ?›

O(n log n) dans tous les cas (log n niveaux × n opérations de fusion) et O(n) de mémoire supplémentaire (tableau temporaire). → ch. 4
